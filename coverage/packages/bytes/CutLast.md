Go calls LastIndex and uses its last matching offset to build two ordinary slice views. The Lean last-match theorem proves that there is no later match, including the empty separator at the source length. The CutLast theorem gives the prefix with original capacity and the suffix with capacity reduced by the match end. Both preserve nilness. A missing separator returns the original slice, nil, and false. The claim excludes backing-array identity and the implementation details of the search. [Pinned source](https://github.com/golang/go/blob/go1.27.0/src/bytes/bytes.go#L1424-L1435)

Go 1.27.0 and Lean agreed on 1,916 boundary pairs and 60,000 samples with seeds 17, 2718, and 65537 on darwin/arm64. The comparison enumerates every matching window in a fixture to determine the final one and checks the resulting slices' contents, capacity, and nilness. Both the default build and the intrinsics-disabled build passed. The latter keeps the platform's bytealg assembly in use where selected. Run `go run difftest/bytes/substring/check.go` after building the registered Lean driver. The second mode adds `-gcflags=command-line-arguments=-d=ssa/intrinsics/off -gcflags=bytes=-d=ssa/intrinsics/off` after `go run`.

The reviewer control passed eight fixtures. Splitting at the first match failed two, including overlapping matches of aba in ababa. Clipping the capacity of both result views failed six. On a padded ababa input with capacity 9, cutting after the last matching aba gives an empty non-nil after view with capacity 4. Run `go run coverage/packages/bytes/controls/CutLast/main.go`.
