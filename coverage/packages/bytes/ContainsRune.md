The public wrapper in pinned Go 1.27.0 reports whether bytes.IndexRune
returns a nonnegative position. The four paths are ASCII byte search,
decoding for RuneError, rejecting invalid target runes, and finding a
complete UTF-8 spelling for other valid targets. The shared Lean search
preserves that result; Go's reverse comparison, optimized candidate
search and fallback are outside the algorithmic scope. A valid complete
UTF-8 encoding starts with a noncontinuation byte, so such a substring
cannot begin inside another successfully decoded rune. A failed decode
advances by one byte. RuneError requires an actual decode because a
malformed byte and the canonical encoding can both produce it.

The author comparison uses Go range decoding as its reference and tests
11,302 deterministic cases and 60,000 samples with seeds 17, 2718 and
65537. The independent control compared pinned Go and Lean on 19 fixed
fixtures on darwin/arm64, including partial UTF-8, surrogate and
out-of-range encodings, literal RuneError, an invalid target alongside a
literal RuneError, and long absent and present searches with repeated
false final-byte candidates. Replacing the search with the target's
encoded bytes failed seven cases. Mapping an invalid target to RuneError
failed three.

Run the installed control from the repository root with
`GOTOOLCHAIN=go1.27.0 GOWORK=off go run ./difftest/bytes/contains-rune/review`
after building the model executable.
