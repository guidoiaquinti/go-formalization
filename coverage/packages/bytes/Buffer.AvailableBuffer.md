Pinned Go 1.27.0 returns `b.buf[len(b.buf):]`, so the view starts at
the stored end independently of the unread offset. Its capacity is
the backing tail length. A zero-capacity view of nonnil storage stays
nonnil, and a zero buffer with nil storage returns nil. A nil receiver
panics. The Lean byte regions preserve these observations.

The wrapper comparison checks append followed by the immediate Write
described in Go's documentation. An append fitting the tail affects
the spare bytes before the write without changing existing unread
bytes. A larger append cannot change the original tail. The checked
Write returns the supplied length and produces the previous unread
bytes followed by the payload. Post-write capacity and allocation
policy remain out of scope. The control did not inspect the retained
view after Write or use storage after transferring it to NewBuffer.

The author checks 10,408 boundaries and 60,000 samples with seeds 17,
2718 and 65537. The independent control passed nine fixed native
darwin/arm64 Go and Lean cases, including nil receiver, nil and nonnil
zero capacity, a partially consumed buffer, exact-fit and overflowing
appends, and empty input. Detaching the view while preserving its
capacity failed two cases. Returning nil for every zero-capacity view
failed two cases.

`GOTOOLCHAIN=go1.27.0 GOWORK=off go run ./difftest/bytes/buffer-available-buffer/review`
after building the model executable.
