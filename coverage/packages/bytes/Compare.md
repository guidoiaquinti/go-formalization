Go delegates to bytealg.Compare. The generic scan stops at the first differing unsigned byte and orders equal prefixes by length. Its shared-base shortcut gives the same result by comparing lengths when both slices start at the same address. The Lean theorem specifies all three outcomes using lexicographic order over unsigned byte values. On the tested darwin/arm64 profile, both build modes select the architecture-specific assembly for bytealg.Compare. Runtime validation of the generic Go implementation is outside this profile. [Pinned wrapper](https://github.com/golang/go/blob/go1.27.0/src/bytes/bytes.go#L25-L30) · [Generic scan](https://github.com/golang/go/blob/go1.27.0/src/internal/bytealg/compare_generic.go#L11-L36)

The registered comparison passed 65,636 boundary inputs, including every single-byte pair, and 60,000 sampled inputs using seeds 17, 2718, and 65537. Go 1.27.0 and Lean agreed in both the default and intrinsics-disabled modes on darwin/arm64. Run `go run difftest/bytes/compare/check.go` after building the Lean executable. The intrinsics-disabled run adds `-gcflags=command-line-arguments=-d=ssa/intrinsics/off -gcflags=bytes=-d=ssa/intrinsics/off` after `go run`.

The control passed nine comparison fixtures, including slices sharing a base with different lengths. Signed comparison failed three, including 0x80 versus 0x7f.
