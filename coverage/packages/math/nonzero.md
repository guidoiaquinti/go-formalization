I checked Go 1.27.0's `nonzero` in `src/math/fma.go`. Its live branch returns 1 for every nonzero uint64 and 0 for zero. The Lean model implements the same test with the zero case first. Its theorem relates the result to the documented branchless expression, where Go's shift binds before the outer subtraction. Folding the low bit into the shifted word preserves whether the input is zero. The unsigned decrement and top-bit extraction yield the zero indicator. Subtracting that indicator from one gives the nonzero result without underflow.

I ran `go run difftest/math/nonzero/check.go` on Go 1.27.0, darwin/arm64. The private Go helper and Lean matched the branchless formula on 258 boundaries and 20,000 generated words per seed 17, 2718, and 65537. The domain includes isolated bits at every position, zero, and arbitrary words.

I ran `go run difftest/math/nonzero/review/main.go`. The control reuses the existing overlay and checks eight fixed uint64 inputs against their concrete expected results. Truncating to uint32 before testing fails on two words whose set bits are entirely above bit 31. Returning the input unchanged fails on six words, including input 2 where the result must be exactly 1.
