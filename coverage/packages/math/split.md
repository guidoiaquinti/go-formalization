I checked the pinned Go 1.27.0 extraction and normalization branches in `src/math/fma.go`. The sign is the top bit, and masks recover the raw exponent and fraction. For a nonzero exponent the source sets bit 52, including for infinity and NaN encodings. For a subnormal with top fraction bit at position k, the leading-zero count is 63-k, so subtracting 11 shifts the bit to position 52. The shifted fraction fits in 53 bits and the resulting exponent is k-51. For signed zero, the count is 64 and shifting zero by 53 gives zero with exponent -52. The Lean theorem gives these same results for every raw input word.

I ran `go run difftest/math/split/check.go` on Go 1.27.0, darwin/arm64. The in-package bridge calls the private helper and checks all three raw result fields.
