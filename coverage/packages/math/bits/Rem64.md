Go first reduces hi modulo y, which raises integer divide by zero when y is zero. For a positive divisor, the reduced high word is strictly below y, so Div64 cannot overflow its quotient. Replacing hi by hi modulo y changes the double-word dividend by a multiple of y, leaving the remainder unchanged. The Lean model abstracts Div64’s division steps and proves the observable result. The Lean theorem covers every operand triple. It proves that only zero triggers a divide-by-zero error and that every returned remainder is below y with a nonnegative quotient witness. It excludes quotient-overflow panics even when hi is at least y. [Pinned source](https://github.com/golang/go/blob/go1.27.0/src/math/bits/bits.go#L587-L599)

Go 1.27.0 and Lean agreed on 1,728 boundary triples and 60,000 samples with seeds 17, 2718, and 65537 in each build mode on darwin/arm64. The direct check builds the dividend in math/big for positive divisors and checks the runtime error type and message for zero. Cases include hi below, equal to, and above y. Run `go run difftest/math/bits/rem64/check.go` after compiling the Lean driver. The intrinsics-disabled mode adds `-gcflags=command-line-arguments=-d=ssa/intrinsics/off -gcflags=math/bits=-d=ssa/intrinsics/off` to the same command. The pinned compiler's dedicated Div64 intrinsic is registered for amd64. [Compiler registration](https://github.com/golang/go/blob/go1.27.0/src/cmd/compile/internal/ssagen/intrinsics.go#L1277-L1287)

The shared control passed eight fixtures per fixed-width entry point in both compilation modes. Substituting division for remainder failed four, using only the low word failed two, and returning zero for a zero divisor failed two. For example, (hi, lo, y) = (4, 0, 3) returns 1, while raw division produces a quotient-overflow panic and the low-word mutant returns 0.
