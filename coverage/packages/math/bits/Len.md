The 64-bit Go wrapper delegates to `Len64`, whose threshold steps and generated byte lookup are modeled by `len64`. Lean's `len` is that same model, and the Go comparison calls `bits.Len` at native uint width and rejects hosts where it differs from 64. The 32-bit Go wrapper is outside this record's scope. The kernel-checked theorem characterizes the result by the fit criterion for every candidate width and includes width zero for input zero. [Pinned implementation](https://github.com/golang/go/blob/go1.27.0/src/math/bits/bits.go#L302-L307) · [Table generator](https://github.com/golang/go/blob/go1.27.0/src/math/bits/make_tables.go#L85-L91)

On Go 1.27.0 darwin/arm64, the registered Go and Lean comparison passed 258 boundary cases and 60,000 samples with seeds 17, 2718, and 65537 in each build mode. The comparison checks an independent repeated-division oracle under default compilation and with intrinsics disabled in both the driver and `math/bits`. The pinned compiler registers `Len32` and `Len64` as arm64 intrinsics and aliases `Len` to `Len64` on 64-bit targets. [Compiler registration](https://github.com/golang/go/blob/go1.27.0/src/cmd/compile/internal/ssagen/intrinsics.go#L1010-L1055)

The shared control checked the exact fit criterion at each width from zero through the word width, including shifts at 64. Both sides are true at larger widths because the input fits in the machine word and the result is bounded. The real Go entry point passed every case in both build modes. Truncating to the low half failed 160 of 258 cases, and substituting population count failed 189 of 258. For example, input `0x0000000100000000` requires 33 bits. Dropping the upper half returns zero and population count returns one. [Reviewer control](controls/WideLength/main.go)
