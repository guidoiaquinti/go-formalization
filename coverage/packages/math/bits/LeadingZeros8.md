I checked Go 1.27.0's width-minus-length implementation in `src/math/bits/bits.go`. The fallback reads the length table generated by counting right shifts to zero. The Lean model mirrors the table generator and factors the wider threshold steps into recursive half-word selection. Its theorem makes the remaining width the minimum number of bits needed to represent the unsigned input. Zero needs no bits and therefore returns 8 leading zeros.

I ran `go run difftest/math/bits/leadingzeros8/check.go` on Go 1.27.0, darwin/arm64, and repeated it with `-gcflags=command-line-arguments=-d=ssa/intrinsics/off -gcflags=math/bits=-d=ssa/intrinsics/off`. Both profiles matched the top-down bit scan on all 256 inputs. Go's compiler supplies arm64 Len intrinsics under default compilation. Disabling them exercises the source length implementation.

I ran the shared `go run coverage/packages/math/bits/controls/LeadingZeros/main.go` control with both profiles. Zero and all 8 words with exactly one bit set passed for this entry point. Counting from the low end instead disagrees on all 8 one-bit words.
