I checked the live comparison and the documented branchless formula in Go 1.27.0's `src/math/fma.go`. The Lean model matches the live branch, and its theorem connects it to the branchless expression. Shifting right by one and ORing the original low bit produces a word below (2^{63}), which is zero exactly when all the input bits are zero. If the folded word is zero, subtracting one wraps and puts a one in bit 63. For every other folded word, subtraction leaves bit 63 clear. The final shift extracts that bit.

I ran `go run difftest/math/zero/check.go` on Go 1.27.0, darwin/arm64. The existing overlay calls the actual private helper. Go and Lean matched the branchless formula on 258 boundaries and 20,000 generated words per seed 17, 2718, and 65537. The domain includes zero, every isolated bit, nearby values, and arbitrary words.

I ran `go run difftest/math/zero/review/main.go`. The overlay control checks eight fixed native inputs against direct zero comparison. A mutant that omits the low-bit OR fails for input 1. A mutant that skips folding and subtracts directly fails twice, including on the largest uint64.
