I checked the pinned Go 1.27.0 helper in `src/math/fma.go`. It independently shifts the high word and ORs three contributions into the low word. On the tested darwin/arm64 profile, `uint` is 64 bits. For (n > 64), the wrapped count (64-n) ranges from 65 through (2^{64}-1). For (n < 64), the wrapped count (n-64) ranges from (2^{64}-64) through (2^{64}-1). Both shift a uint64 word completely away. At 64, both differences are zero and the two contributions copy the same high word. The Lean guards implement these cases and the theorem gives equality on every bit of the joined unsigned result. Lean's natural counts include all native uint values, and the driver encodes the native count losslessly into a 64-bit word. The same wrap argument works for a 32-bit uint, which was not tested in this replay.

I ran `go run difftest/math/shr/check.go` on Go 1.27.0, darwin/arm64. The overlay invokes the actual private helper. Go and Lean matched a joined-value math/big oracle on 400 boundaries and 20,000 generated cases per seed 17, 2718, and 65537. The boundary grid includes the zero count, the transitions around 64 and 128, and the maximum native uint.

I ran `go run difftest/math/shr/review/main.go`. The control reuses the same-package overlay bridge and fixture. The native helper passed eight fixed inputs. Shifting each word independently fails on five, including shift 1 of high=1 and low=3. Masking the count modulo 128 fails on shift 128 of the same input, reproducing the original words where Go returns zeros.
