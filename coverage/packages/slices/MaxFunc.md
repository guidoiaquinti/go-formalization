I checked Go 1.27.0's implementation in `src/slices/sort.go`. It compares each next element with the current best and replaces the best only for a strictly positive result. The Lean theorem assumes that the relevant sign agrees with strict integer-key ordering. It proves the maximum key bound and that the result is the first element attaining that bound. For MaxFunc, the model tests the negated comparator result in Lean Int, where negation is exact even when the original Go result is MinInt. Callback side effects, nil callbacks, and comparator panics are outside this scope.
