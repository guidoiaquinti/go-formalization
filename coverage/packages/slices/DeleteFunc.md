I checked Go 1.27.0's `DeleteFunc` and `IndexFunc` in `src/slices/slices.go`. The initial search visits elements in order without writing until one qualifies for removal. The second loop visits each original element after that position and moves retained elements to the next available slot. The destination always precedes the currently visited source, so subsequent calls still receive the original values. On success the clear zeros the tail. A predicate panic skips the clear and leaves completed writes in place. The Lean theorems prove the value sequence and trace for a pure predicate, and the completed-prefix and original-suffix relation for a predicate that panics. The model uses fixed original values and excludes nil callbacks and callbacks mutating the backing array.
