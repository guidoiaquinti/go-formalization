Go adds one to the low word, carries into the high word when necessary, and tests for overflow using the original family. Native IPv4 overflows at 32 bits, while IPv6 and IPv4-mapped IPv6 use the 128-bit branch. The Lean theorem specifies the carry, wrapping and preservation of the family and zone except when the source returns the zero Addr. The model includes the pinned behavior for a zero receiver. It returns an invalid address whose raw bits end in one. Whether the documented no-successor rule applies to that receiver remains an open question in FINDINGS.md. [Pinned source](https://github.com/golang/go/blob/go1.27.0/src/net/netip/netip.go#L743-L759) · [Lean model](../../../../lean/GoLean/Net/Netip/AddrNext.lean) · [Finding](../../../../FINDINGS.md)

The Go driver constructs addresses through the public APIs and checks the bit length, raw bytes and zone against a bytewise increment. Go 1.27.0 and Lean agreed on 16 boundaries and 60,000 sampled cases on darwin/arm64, using seeds 17, 2718 and 65537. The samples cover IPv4, IPv6, mapped IPv6 and zones. [Differential comparison](../../../../difftest/net/netip/addr-next/check.go)

Go passed all six independent fixtures. Treating the invalid input as unchanged failed the zero-receiver fixture. Dropping the high-word carry failed one case. Dropping the zone failed two. The zero-receiver control separately checks invalidity, 16-byte representation and inequality to Addr{}. [Reviewer control](controls/AddrNeighbor/main.go)
