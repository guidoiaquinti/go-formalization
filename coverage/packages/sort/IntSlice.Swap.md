## Earlier comparison note

The first model checked the right-hand operands in written order. For a
non-nil empty slice with `i = -1` and `j = 0`, that predicted an index
`[0]` panic with length zero. Go 1.27.0 on darwin/arm64 reported index
`[-1]`, and the slice remained empty. The model now checks the indexed
destinations in order before applying either write.

Run `make build`, then run
`GOTOOLCHAIN=go1.27.0 GOWORK=off go run ./difftest/sort/intsliceswap`
to replay this boundary case with the corrected expectation.
