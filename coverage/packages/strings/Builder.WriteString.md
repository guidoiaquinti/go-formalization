The pinned method runs the copy check before append and returns the input byte length with a nil error. The Lean model records identity on first use, appends bytes on success, and preserves contents when a previously initialized copy panics. Nil receiver panic is a separate case. Allocation sizing and failures are outside the claim. [Pinned copy check](https://github.com/golang/go/blob/go1.27.0/src/strings/builder.go#L32-L42) · [Pinned write implementation](https://github.com/golang/go/blob/go1.27.0/src/strings/builder.go#L110-L116) · [Lean model](../../../lean/GoLean/Strings/BuilderWriteString.lean)

Go 1.27.0 and Lean agreed on 352 boundaries and 60,000 samples from seeds 17, 2718, and 65537 on darwin/arm64. The driver observes the actual identity pointer, count and error, panic payload, accumulated bytes, and preservation of earlier strings. [Go comparison](../../../difftest/strings/builder-write-string/check.go)

The independent control checks a copy of untouched zero state, a copy after a nonempty write, a copy after an empty first write, and subsequent ordinary append. Go passed. Omitting the copy check would let both initialized copies write, while skipping identity setup for empty input would let the copy of that builder write.
