Go 1.27.0 compares ASCII bytes directly until either input calls for
the Unicode path. That path consumes one decoded rune from each string,
rejects exhaustion on either side, and walks the sorted SimpleFold
cycle from the smaller rune until it reaches or passes the larger one
or wraps. Fixed-width byte matching would lose fold pairs with different
UTF-8 widths, and consecutive malformed bytes each consume one byte and
produce separate RuneError values. The Lean Unicode path gives at most
one comparison per byte of the first string, which suffices because the
decoder always consumes at least one byte in nonempty input.

I regenerated the table using pinned Go and confirmed a byte-for-byte
match. The generator writes nonidentity pairs in ascending input rune
order, and identity is the search default. The author comparison checks
all 1,114,112 successor results and confirms the maximum observed orbit
size of four, justifying the search fuel. It also checks 72,644 fixed
string pairs and 60,000 samples using seeds 17, 2718 and 65537, using
canonicalized decoded sequences instead of the source's ordered
pairwise walk.

The independent control checked 21 fixed Go and Lean strings and 18
explicit successor pairs on darwin/arm64. The fixtures include the
four-member Greek theta cycle, the long-s and Kelvin cycles, an astral
pair, no expansion for ligatures and sharp s, and malformed-width and
tail cases. Replacing comparison with lowercase strings failed four
