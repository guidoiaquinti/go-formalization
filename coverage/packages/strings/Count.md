I checked Go 1.27.0's three branches in `src/strings/strings.go`. The empty separator returns one plus the number of UTF-8 decode steps. The width model follows the lead and continuation byte ranges, with malformed or incomplete encodings consuming one byte. A singleton separator delegates to byte counting, and longer separators search left to right and discard the input through the end of each match. The Lean theorem equates the search-and-discard recursion with a position-by-position greedy count. The empty-separator equality identifies the modeled decode count. The width rules and native optimized search and counting are checked by the differential and are outside that proof.

I ran the shared control, `go run coverage/packages/strings/controls/TrimCount/main.go`. All seven count fixtures passed.
