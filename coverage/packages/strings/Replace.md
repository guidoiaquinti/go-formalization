Go 1.27.0 returns the input bytes when old equals new or the signed
limit is zero, counts matches, then clamps the number of replacements.
Every negative limit selects all matches, including the native minimum
int without negating it. For nonempty old strings it advances by the
full matched width, including raw byte matches spanning invalid or
partial UTF-8. For empty old strings it first inserts at offset zero
and subsequently at each decoded rune boundary. A malformed byte
consumes one byte and a literal RuneError consumes three. The model
preserves these paths and returned bytes. Builder allocation, backing
identity, and results too large for Go int remain outside scope.

The author comparison independently collects candidate offsets and
constructs the output using 25,125 boundaries and 60,000 samples
with seeds 17, 2718 and 65537. The independent control checked 16 fixed
Go and Lean cases on darwin/arm64. They include zero, positive and
minimum and maximum signed limits, malformed and valid empty-old
boundaries, absent and unchanged patterns, two overlapping patterns,
and raw matches inside a rune or across malformed input. Treating
zero as unlimited, allowing overlaps, and inserting at raw byte
boundaries each failed two cases.
