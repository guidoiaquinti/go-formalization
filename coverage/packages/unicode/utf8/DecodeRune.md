The pinned slice decoder returns RuneError with width zero for an empty slice and bypasses the multibyte classifier for ASCII. The remaining acceptance table, length checks, continuation checks, and payload assembly match the string entry point. The Lean theorem proves that the models agree on the same bytes, including empty input. Agreement of the Lean classifier with the pinned Go tables is tested across the comparison domain. [Pinned slice source](https://github.com/golang/go/blob/go1.27.0/src/unicode/utf8/utf8.go#L157-L208) · [Pinned string source](https://github.com/golang/go/blob/go1.27.0/src/unicode/utf8/utf8.go#L219-L266)

The comparison calls Go's slice decoder directly, checks the independent scalar oracle and Lean output, and includes nil and non-nil empty slices. The pinned run on darwin/arm64 passes 65,809 boundary cases, including all one- and two-byte slices, and 60,000 samples using seeds 17, 2718, and 65537. Run `go run difftest/unicode/utf8/decode-rune/check.go` after building the registered Lean executable.

The separate control checks both Go entry points on eight fixtures and checks that the slice contents are preserved on those fixtures. Returning the entire slice length as the width fails four, and collapsing a correctly encoded U+FFFD to width one fails one. Run `go run coverage/packages/unicode/utf8/controls/DecodeRune/main.go`.
